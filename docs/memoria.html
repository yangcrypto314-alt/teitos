2. Cómo se arranca

Hace falta Node.js 20 o superior. En la carpeta del proyecto:

npm install          # instala dependencias (json-server 1.0.0-beta.15 incluido)
npm run reset-datos  # db.original.json → db.json con solicitudes vacía
npm start            # web en http://localhost:5173 y API en http://localhost:3001

Otros comandos: npm run build genera dist/ y npm run lint revisa el código con oxlint.

3. Decisiones tomadas

  • Se piden las 1.200 viviendas una vez y se filtra en el cliente. json-server no aplica la regla de acceso (ingresos y personas no son un campo) ni la búsqueda sin tildes. Filtrar en memoria permite combinar todo y es instantáneo (ver apartado 6).
  • Los filtros viven en la URL. La búsqueda se puede pegar en un correo, y los botones atrás/adelante del navegador funcionan. Se usa replace para no llenar el historial con cada tecla.
  • Unión manual en vez de _embed. useVivienda pide la vivienda y después su convocatoria. Si la convocatoria falla, la vivienda se muestra igualmente.
  • Tipos de id. id es texto y convocatoriaId es número, así que se comparan con String().
  • Una solicitud = una convocatoria, máximo 3 viviendas. La función motivoRechazo() del reducer explica al usuario por qué no se puede añadir.
  • Modal con <dialog> nativo. Atrapa el foco, se cierra con Esc y devuelve el foco sin depender de librerías.
  • Patrón activo en los hooks. Evita actualizar el estado de un componente desmontado. recargar() incrementa una versión para repetir la petición.
  • «Sin dato» ≠ «Sin adaptar». accesibilidad: null se muestra como «Dato de accesibilidad no disponible».

5. Los tres estados

Cada hook devuelve cargando, error y vacio, y la página elige qué pintar con el componente Estado:

Cargando: tarjetas esqueleto grises con brillo animado (se desactiva con prefers-reduced-motion) y texto oculto «Cargando…» para el lector de pantalla (role="status").
Error: etiqueta «ERROR DEL SERVIDOR», explicación y botón Reintentar, que llama a recargar() y repite la petición sin recargar la página (role="alert"). Un 404 en el detalle se trata aparte: «La vivienda X no existe».
Vacío: «No hay resultados» con el botón Limpiar filtros, que borra los parámetros de la URL.

Prueba realizada: se forzó un fallo de fetch y apareció el estado de error. Al restaurar la red, «Reintentar» cargó las 979 viviendas libres.

6. Medida de rendimiento propia

Se midió en la build de producción (vite preview), con performance.now(), la petición de viviendas y el filtrado. Fueron 5 repeticiones sin caché, buscando «coruna» (encuentra «A Coruña» sin tilde ni eñe) y ordenando por renta:

MedidaResultado
Tamaño de /viviendas (1.200 registros)564 KB
Petición + descarga (local)34 – 50 ms (mediana 42 ms)
Normalizar + filtrar + ordenar en el cliente0,6 – 1,7 ms → 121 resultados
JavaScript de la build312 KB (97 KB con gzip)
CSS de la build32 KB (6,8 KB con gzip)
DOMContentLoaded de la página45 ms

Conclusión: filtrar en el cliente cuesta menos de 2 ms, menos que un fotograma (16 ms), así que los filtros responden al momento mientras se escribe. Lo que más pesa es la descarga de las 1.200 viviendas, que se hace una sola vez al entrar al buscador. Además, el filtrado va dentro de useMemo y solo se recalcula cuando cambian los datos o los filtros. Las ilustraciones usan loading="lazy" y solo se descargan las 12 de la página visible.

7. La versión publicada sin el servidor de datos

La web se publica en GitHub Pages con un workflow que compila con la ruta base del repositorio y copia index.html a 404.html, para que funcionen las URL de React Router al recargar. GitHub Pages solo sirve ficheros estáticos y no puede ejecutar json-server, y la URL de la API apunta a localhost:3001. Por eso:

  • La interfaz carga entera: cabecera, portada, buscador, navegación, la página 404 y el formulario.
  • Cada petición falla y se muestra el estado de error con «Reintentar», nunca una pantalla en blanco.
  • Para verla con datos hay que clonar el repositorio y arrancarla en local con npm start.
  • La selección y el borrador siguen guardándose en localStorage.
