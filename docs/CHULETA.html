Chuleta de defensa · Teitos

Portal de alquiler asequible · SPA en React 19 + Vite + React Router 7 + json-server 1.0.0-beta.15 · Proyecto 1 PMDM

La idea en una frase: «Es una SPA en React que pide los datos a una API REST local hecha con json-server. Los datos pasan por la carpeta api/, los piden mis hooks con useEffect, las páginas los filtran y los pintan con componentes pequeños, y la solicitud se guarda en un Context con useReducer que se copia en localStorage.»

0 · Antes de empezar (10 min antes)

  1. Abrir terminal en la carpeta del proyecto → npm install (si es otro PC) → npm run reset-datos → npm start.
  2. Comprobar http://localhost:5173 (web) y http://localhost:3001/viviendas (API).
  3. Tener abiertos en VS Code: reglas/acceso.js, pages/Viviendas.jsx, hooks/useViviendas.js, context/solicitudReducer.js, api/cliente.js.
  4. Pestañas del navegador: la web, Figma (prototipo) y GitHub.
  5. Si algo se rompe en directo: Ctrl+Z en VS Code y guardar; Vite recarga solo. Si la API se queda rara: parar (Ctrl+C), npm run reset-datos, npm start.

4 · El código que más preguntan (apréndete esto)

4.1 Un hook con sus 3 estados — hooks/useViviendas.js

const [version, setVersion] = useState(0);
const [resultado, setResultado] = useState({ version: -1, datos: [], error: null });
const recargar = useCallback(() => setVersion(v => v + 1), []);   // botón Reintentar

useEffect(() => {
  let activo = true;                       // ¿sigue montado el componente?
  getViviendas()
    .then(lista => { if (activo) setResultado({ version, datos: lista.filter(v => !v.adjudicada), error: null }); })
    .catch(e    => { if (activo) setResultado({ version, datos: [], error: e.message }); });
  return () => { activo = false; };        // limpieza: si me desmonto, ignoro la respuesta
}, [version]);                             // se repite cuando cambia version

const cargando = resultado.version !== version;   // aún no ha llegado la respuesta de ESTA petición
const vacio = !cargando && !error && datos.length === 0;

Explicación: el useEffect se ejecuta al montar y cada vez que cambia version. Guardo junto a los datos a qué petición pertenecen; si no coincide con la actual, estoy cargando. activo evita actualizar un componente que ya no existe. recargar suma 1 a version → se repite la petición.

4.2 La función que hace todas las peticiones — api/cliente.js

export const API_URL = 'http://localhost:3001';
export async function pedir(ruta, opciones) {
  const respuesta = await fetch(`${API_URL}${ruta}`, opciones);
  if (!respuesta.ok) { const error = new Error(`Error ${respuesta.status} al pedir ${ruta}`); error.estado = respuesta.status; throw error; }
  if (respuesta.status === 204) return null;
  return respuesta.json();
}

fetch no falla con un 404 o 500, solo si no hay red; por eso compruebo respuesta.ok (true si 200–299). error.estado me deja distinguir «no existe» (404) de «error del servidor».

4.3 La regla de acceso — reglas/acceso.js

IPREM_ANUAL = 8400;  VECES_MINIMO = 2;  VECES_MAXIMO = 7.5;  ESFUERZO_MAXIMO = 0.3;
PONDERACION = { 1: 1, 2: 1.15, 3: 1.3, 4: 1.45, 5: 1.6 }   // 6 o más → 1.75
rangoIngresos(p) = { minimo: 8400 × pond × 2,  maximo: 8400 × pond × 7.5 }
rentaMaxima(ingresos) = ingresos / 12 × 0.3
puedeAcceder(v, ingresos, personas) = cumpleIngresos(...) && v.renta <= rentaMaxima(ingresos)
Ejemplo para decir de memoria: 2 personas → 8.400 × 1,15 = 9.660. Mínimo 9.660 × 2 = 19.320 €, máximo 9.660 × 7,5 = 72.450 €. Con 30.000 € cumple, y la renta máxima es 30.000 / 12 × 0,3 = 750 €/mes. En Pontevedra salen 116 viviendas.

4.5 El reducer — context/solicitudReducer.js (resumido)

case 'anadir': if (motivoRechazo(estado, accion.vivienda)) return estado;
               return { ...estado, seleccion: [...estado.seleccion, accion.vivienda] };
case 'quitar': return { ...estado, seleccion: estado.seleccion.filter(s => s.id !== accion.id) };
case 'mover':  { const i = …findIndex; const j = i + accion.desplazamiento;   // -1 sube, +1 baja
                 const copia = [...estado.seleccion]; [copia[i], copia[j]] = [copia[j], copia[i]]; … }
case 'campo':  return { ...estado, borrador: { ...estado.borrador, [accion.campo]: accion.valor } };
case 'enviada': return { ...estadoInicial, solicitudId: accion.id };   // limpia todo y guarda el id

Un reducer es una función pura (estado, accion) → nuevo estado. Nunca modifica el estado: crea copias con ... (spread). Se llama con dispatch({ tipo: 'anadir', vivienda }). motivoRechazo impide repetir, pasar de 3 o mezclar convocatorias.

6 · Preguntas típicas y respuestas

¿Qué es una SPA?

Una sola página HTML; React cambia el contenido sin recargar. La URL cambia con React Router.

¿Por qué json-server?

Crea una API REST falsa a partir de un JSON en segundos: GET, POST, PUT, DELETE sin programar un backend.

¿Qué es db.original.json?

Los datos tal como me los dieron. No se toca. npm run reset-datos lo copia a db.json con solicitudes: [].

¿Por qué crear «solicitudes» vacía?

json-server 1.0 no crea colecciones nuevas: sin ella el primer POST da 404.

¿Dónde está la URL del servidor?

Solo en api/cliente.js. Ningún componente hace fetch.

¿Por qué compruebas respuesta.ok?

fetch solo falla sin red; un 404 o 500 «funciona». Con ok lo convierto en error.

¿Qué tres estados tiene cada petición?

Cargando (esqueleto gris), error (aviso + Reintentar) y vacío (mensaje + Limpiar filtros). Componente Estado.

¿Por qué el id es texto y convocatoriaId número?

Así vienen de json-server. Comparo con String() (Inicio) o comparo números con números (reducer).

¿Por qué no usas _embed?

No funciona con estos datos. Pido la vivienda y luego su convocatoria (useVivienda).

¿Cómo quitas las adjudicadas?

En useViviendas: lista.filter(v => !v.adjudicada). De 1.200 quedan 979.

¿Cómo buscas sin tildes?

normalizar() en los dos lados: normalize('NFD') + quitar [\u0300-\u036f] + minúsculas.

¿Por qué los filtros en la URL?

Para poder copiar y pegar la búsqueda; además funcionan Atrás/Adelante y F5.

¿Por qué «personas» e «ingresos» no comparan un campo?

Las viviendas no tienen esos campos: aplican la regla del IPREM de reglas/acceso.js.

¿Qué pasa si solo pongo ingresos?

La regla necesita los dos; aviso «indica las personas y los ingresos» y no filtra por ellos.

¿Cómo paginas?

En el cliente: slice((pagina-1)*12, pagina*12). La página va en la URL. Al cambiar filtros, vuelve a la 1.

¿Por qué useMemo en el filtrado?

Para no refiltrar 979 viviendas en cada render, solo si cambian datos o filtros.

¿Por qué useReducer y no useState?

El estado de la solicitud tiene muchas acciones; el reducer las centraliza y es fácil de probar.

¿Por qué Context?

Varias páginas usan la solicitud (Detalle añade, Solicitud la rellena, BarraMovil cuenta). Sin Context pasaría props por todo.

¿Cómo sobrevive a F5?

El Provider guarda el estado en localStorage en un useEffect y lo lee al arrancar (cargarEstado).

¿Qué guardas en localStorage?

Selección, borrador, paso actual y el id de la solicitud enviada (clave teitos-solicitud).

¿Por qué máximo 3 viviendas de una convocatoria?

Una solicitud es para una convocatoria. MAX_PREFERENCIAS y motivoRechazo().

¿Cómo ordenas las preferencias?

Acción mover con desplazamiento -1/+1: intercambio las posiciones i y j en una copia del array.

¿Validación al vuelo y al enviar?

Al vuelo: error visible cuando el campo está «tocado». Al pulsar Siguiente/Enviar: marco todos como tocados y no avanzo.

¿Qué datos manda el POST?

convocatoriaId, viviendas (ids en orden), solicitante, hogar, fechaEnvio, estado: 'enviada'.

¿Cuándo se puede modificar o retirar?

Solo si convocatoria.estado === 'abierta'. Si no, oculto los botones y lo explico.

¿PUT o PATCH?

PUT: mando la solicitud completa (...solicitud + cambios). Es lo que pide el enunciado.

¿Qué hace el modal accesible?

<dialog> con showModal(): foco dentro, Esc cierra, fondo inerte, título con aria-labelledby.

¿Cómo es accesible la app?

Todo con teclado, foco amarillo visible, «Saltar al contenido», label en cada campo, role="alert"/"status", aria-current, nada solo por color (iconos + texto).

¿«Ninguna información depende solo del color»?

Estados con icono (● ✓ ▲ !) y texto; página activa subrayada; errores con «!» + mensaje.

¿Responsive?

Media queries a 900, 760 y 560 px; grid con minmax; menú hamburguesa y barra inferior en móvil. Sin scroll horizontal a 390 px.

¿CSS Modules por qué?

Clases locales a cada componente: no chocan nombres. Lo pide el enunciado (sin Bootstrap/Tailwind).

¿Relación Figma ↔ código?

Mismos nombres de variables (--color-primario) y un componente React por componente de Figma con sus variantes como props (Boton variante, Estado tipo).

¿Qué hace la versión publicada sin servidor?

Carga la interfaz; las peticiones fallan y muestra el estado de error con Reintentar. Para datos, npm start en local.

¿Cómo se publica?

GitHub Actions: build con base /teitos/, copia index.html a 404.html (para que funcionen las rutas al recargar) y lo sube a Pages.

¿Medida de rendimiento?

Descarga de viviendas ≈ 42 ms (564 KB); filtrar+ordenar < 2 ms; JS 97 KB gzip; imágenes loading="lazy".

¿Por qué la variable «activo» en los hooks?

Si cambio de página antes de que llegue la respuesta, no actualizo un componente desmontado (y StrictMode ejecuta el efecto dos veces).

¿Qué haría con más tiempo?

Paginación en el servidor (_page), arrastrar para ordenar, tests, login real y API desplegada.

¿Por qué el error 404 en /viviendas/99999?

pedir lanza error con estado 404; Detalle lo detecta y muestra «La vivienda no existe».

¿Qué es key y por qué?

Id único en listas; React lo usa para saber qué elemento cambió. Uso v.id, nunca el índice si la lista se reordena.
